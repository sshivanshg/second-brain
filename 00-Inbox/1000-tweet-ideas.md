## How to use this file

- Sections are organized by **format** (hook type) and **niche**. Mix and match.
- `[X]` = fill in a specific number. Specificity beats vague claims by 3.4x.
- Post 30-60 minute engagement decides reach — pick tweets you can defend in replies.
- Replies are weighted **27x** more than likes. Tweets that start arguments or invite stories beat tweets that broadcast.
- Hook in the first 3–5 words. Numbers, contradictions, confessions outperform.
- Posting cadence: 3–5 standalone tweets/day + 1 thread/day + heavy replying on big accounts.

## 13. Machine Learning — Practical tips & gotchas

691. Always normalize your inputs. Always. Yes, even that one.
692. If your loss is NaN, the bug is in your data pipeline 80% of the time.
693. Tokenization is 50% of LLM behavior. The other 50% is the data. The model is the boring part.
694. Set `seed_everything()`. Reproducibility isn't optional.
695. Don't trust a metric you can't explain to your PM.
696. The cheapest 10% accuracy gain: clean labels.
697. Train/test split first. Always. Before EDA. Before anything.
698. Class imbalance? Don't oversample. Reweight loss. Easier. Cleaner.
699. Use a validation set bigger than you think. Variance lies.
700. Log everything. Inputs. Outputs. Metadata. Future-you needs it.
701. Use HuggingFace's `Accelerate` instead of vanilla DDP. Saves a weekend.
702. PyTorch Lightning is great if you don't need control. Vanilla PyTorch if you do.
703. Don't trust a benchmark you can't reproduce locally in 5 minutes.
704. Mixed precision (bf16) is free perf if your hardware supports it.
705. `torch.compile` works. Sometimes. Test before you celebrate.
706. The fastest path to a working baseline: copy a notebook. Iterate. Don't write from scratch.
707. Embedding similarity ≠ semantic similarity. Always sanity check with examples.
708. Use cosine similarity for normalized embeddings. Use dot product for unnormalized. Don't mix.
709. RAG without re-ranking is just search with extra steps.
710. Hybrid search (BM25 + vector) beats vector-only 80% of the time.
711. Chunk size matters more than embedding model in RAG.
712. Track latency before accuracy. Users feel one. Don't notice the other.
713. The most underrated optimizer: AdamW with a sane warmup. Stop changing it.
714. Learning rate is the only hyperparameter that matters. Tune it first. Often only.
715. Use `wandb` for experiment tracking. Use `dvc` for data versioning. Both. Day 1.
716. The "perfect" dataset doesn't exist. Ship with what you have. Fix at scale.
717. Most ML "drift" is just upstream pipeline changes nobody documented.
718. Models age. Datasets age faster.
719. The cheapest evaluation: print 20 outputs and read them.
720. The cheapest unit test for an LLM: assert that output is non-empty and parseable.
721. Synthetic eval data > no eval data. Just label what matters.
722. Don't deploy models without a kill switch. Period.
723. Shadow-mode your new model for 1 week before promotion. Always.
724. Track 3 metrics in prod: accuracy proxy, latency, cost. That's it. Stop dashboard hoarding.
725. Use prompts as the smallest deployable unit. Version them. Roll them back.
726. Cache LLM outputs aggressively. Same input → same output → don't pay twice.
727. The biggest LLM cost saver: shorter prompts. Yes, really.
728. Streaming responses cuts perceived latency by 5x. Free win.
729. Top-K and top-P interact in weird ways. Pick one. Lock it. Test the other.
730. Temperature 0 isn't deterministic. Surprise. Use seed too.
731. The right way to handle JSON output from LLMs: enforce schema with grammars, not regex.
732. Most "agent loops" don't need a planner. They need better tools.
733. The most important agent tool: "I don't know." Add it. Watch hallucinations drop.
734. Eval should be a CI step, not a Notion doc.
735. The fastest model improvement: stop using one prompt for all use cases.
736. Few-shot examples > zero-shot prompting 95% of the time.
737. Chain-of-thought adds latency, sometimes accuracy. Measure before you ship.
738. Function calling > parsing free text. Always. Stop being clever.
739. The right LLM for your task: try the smallest first. Move up only when it fails on a real eval.
740. Don't fine-tune for tone. Use a system prompt. Save the fine-tune budget for capabilities.

- 3 standalone tweets/day (mix: 1 hot take, 1 vulnerable, 1 tactical)
- 1 thread/week — pick from §17 hooks
- 1 reply-bait/week — §14 or §15
- 1 poll/week — §18

**Engagement window (first 30–60 min is decisive)**
- Reply to every reply within 30 min if you can
- Quote-tweet 1–3 of the best replies
- Don't add links to the main tweet — put them in a reply

**Format multipliers**
- Add a screenshot to every revenue / launch tweet (MRR meters auto-engage)
- Add a 30-second screen-recording to feature launches (10x text-only)
- Use line breaks. Whitespace is a feature.

**What NOT to do**
- Don't post a "DM me for the doc" without actually DMing back
- Don't fake numbers — Twitter forensics is unforgiving
- Don't post the same hook twice in 30 days
- Don't quote-tweet your own threads to "boost" — costs reach

1 deep insight → 1 thread → 5 standalone tweets → 1 newsletter section → 1 LinkedIn post
